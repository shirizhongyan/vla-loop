# 最终训练权重：下载与还原

项目提供两份最终 10k 步增量权重，下载入口为本仓库
[Final LIBERO-Spatial models Release](https://github.com/shirizhongyan/vla-loop/releases/tag/final-spatial-10k)。

| 增量包 | 对应历史完整评测 | 组成 |
| --- | --- | --- |
| `vla-loop-l1-10000-delta.tar.gz` | L1，478/500，95.6% | LoRA、L1 动作头、处理器、源码配置与动作统计 |
| `vla-loop-fm-10000-delta.tar.gz` | FM 单步推理，435/500，87.0% | LoRA、速度预测动作头、噪声动作投影器、处理器、源码配置与动作统计 |

增量包不是完整模型，不能直接传给评测脚本。它不含官方底座分片、数据集、
训练优化器状态或中间 checkpoint。下载官方底座一次，两份增量包可共用它。
动作头、投影器和归一化统计都属于模型必需材料，不能只保留 LoRA。

## 1. 准备代码与环境

按 [复现步骤](复现.md) 安装 Linux / Python 3.10 环境和固定版本依赖，
尤其是 OFT 的 Transformers 分支与 PEFT 0.11.1。不要使用同版本号的 PyPI
Transformers 替代该分支。

```bash
git clone https://github.com/shirizhongyan/vla-loop.git
cd vla-loop
export VLA_WORKSPACE="$HOME/vla-work"
WITH_FLOW_MATCHING=1 bash scripts/prepare_sources.sh
```

完整范式补丁支持这两种动作头。若只使用历史 L1 配方，也可采用默认源码准备流程；
不要把两个重叠补丁连续应用到同一工作目录。

## 2. 下载增量包与固定版本底座

```bash
mkdir -p models/deltas
gh release download final-spatial-10k \
  -R shirizhongyan/vla-loop -D models/deltas \
  -p '*-delta.tar.gz' -p SHA256SUMS

cd models/deltas
sha256sum -c SHA256SUMS
tar -xzf vla-loop-l1-10000-delta.tar.gz
tar -xzf vla-loop-fm-10000-delta.tar.gz
cd ../..

hf download openvla/openvla-7b \
  --revision 47a0ec7fc4ec123775a391911046cf33cf9ed83f \
  --local-dir "$HOME/vla-models/openvla-7b-base"
```

`hf` 来自 Hugging Face Hub CLI；安装基础环境时一并准备。底座必须使用上述提交，
不能下载任意“最新版本”后认为模型相同。还原程序会对每个底座分片和增量文件执行
SHA-256 校验；下载失败时不要跳过校验。校验和也不能替代对发布者和来源的信任。

## 3. 在 CPU 上合并还原

使用前面安装好的 OFT Python 环境运行，不需要 GPU。输出目录必须不存在，
脚本不会覆盖已有模型。CPU 合并建议准备至少 48 GiB 可用内存；底座约 14 GiB，
每个完整输出约 15 GiB，此外还需增量包与临时文件空间。

```bash
PYTHON="$VLA_WORKSPACE/openvla-oft/.venv/bin/python"

"$PYTHON" scripts/restore_model_delta.py \
  --bundle models/deltas/vla-loop-l1-10000-delta \
  --base "$HOME/vla-models/openvla-7b-base" \
  --output "$HOME/vla-models/vla-loop-l1-10000"

"$PYTHON" scripts/restore_model_delta.py \
  --bundle models/deltas/vla-loop-fm-10000-delta \
  --base "$HOME/vla-models/openvla-7b-base" \
  --output "$HOME/vla-models/vla-loop-fm-10000"
```

脚本仅读取底座，先在独立临时目录中用 BF16 加载，按 PEFT 方式合并 LoRA，
再保留对应动作组件、配置和处理器；完成后输出 `RESTORE_REPORT.json`。
若只想检查文件完整性、不加载模型，可使用 `--verify-only` 并省略 `--output`。

## 4. 仿真评测

仍需按上游说明配置 LIBERO 的环境资产和默认初始状态。仅评测不需要下载
用于微调的 RLDS 示教数据。没有真机时也可通过 EGL 无头渲染进行仿真。

```bash
VLA_WORKSPACE="$HOME/vla-work" \
CHECKPOINT="$HOME/vla-models/vla-loop-l1-10000" GPU=0 \
  bash scripts/eval_oft.sh

VLA_WORKSPACE="$HOME/vla-work" \
CHECKPOINT="$HOME/vla-models/vla-loop-fm-10000" \
GPU=0 STEPS="1" TRIALS=50 LOG_ROOT="$HOME/vla-fm-evals" \
  bash scripts/eval_step_sweep.sh
```

历史设置为单相机、无 proprio、8-bit 推理、8 步动作块、seed 7，
每个任务 50 次。更改精度、图像输入、积分步数、动作执行长度或初始状态，
就不再是完全相同的评测配置。

## 验证与使用边界

发布前实际验证增量包的哈希、底座分片哈希、还原后的模型张量，
并用还原模型完成仿真加载与动作执行短跑。具体校验数量和短跑结果见 Release
附件 `restore-validation.json`。短跑不是重新完成 500 次评测，也不保证任意硬件上
逐回合结果完全一致。

增量包包含自定义 Python 模型代码与 `.pt` 动作组件，仅加载可信来源。
上游 OpenVLA / OFT 许可随包放在 `LICENSES/`；数据、环境及各底座组件的条款
仍按各自项目执行。
