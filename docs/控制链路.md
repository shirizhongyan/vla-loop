# 从模型动作到机械臂

## 先看一条完整链路

```text
LIBERO 图像 + 任务指令
        ↓
双视觉编码器 → 视觉特征投影 → 语言模型
        ↓
原版：7 个动作 token → 解码与反归一化
OFT：连续动作头 → 8 × 7 动作块 → 反归一化
        ↓
逐步取出动作 → 夹爪归一化与方向转换
        ↓
env.step(action)
        ↓
robosuite OSC_POSE → 关节力矩
        ↓
MuJoCo 动力学步进 → 新图像与状态
```

原版每次预测一个 7 维动作；本次 OFT 每次预测 8 个动作，依次执行后再查询模型。每一步底层控制器与物理引擎仍继续工作，并不是机械臂 8 步内不受控制。

## 七个数表示什么

前 3 维控制末端平移，接下来 3 维控制末端旋转，最后 1 维控制夹爪。

模型输出经过数据统计反归一化后，仍需按仿真控制器约定解释。它不是关节角，也不是直接以米给出的世界坐标目标；位置和旋转指令会经过 OSC 的缩放、裁剪和目标构造。

例如一个正的竖直方向指令表达“让末端朝上移动的意图”，不能直接把该数值当成实际抬升距离。实际位移还受控制器、接触和动力学响应影响。实际坐标约定应以环境中的控制器配置与目标更新代码确认。

## 模型看到状态了吗

环境 observation 中可以包含关节位置、末端位姿和夹爪状态。但“环境提供”与“策略使用”是两回事。

本次原版 OpenVLA 与 OFT 都使用图像、语言。OFT 显式设置 `use_proprio=False`，不把关节或末端状态作为额外策略输入。控制器仍会读取机器人状态来计算力矩。

## 与规划控制的连接

VLA 策略给出下一段操作意图，控制器负责根据当前机器人状态执行。这个分工与“规划轨迹 + 跟踪控制”有相通之处，但机械臂有不同的运动学、接触约束和动作接口。

雅可比描述小范围关节变化与末端变化的关系，局部形式为 `Δx ≈ J(q) Δq`。伪逆可以给出一种局部关节增量解；它不自动解决关节限位、碰撞、奇异位形、接触或稳定力矩控制。把这个局部实验和完整闭环控制区分开，才方便继续定位模型层与执行层的问题。
