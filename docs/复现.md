# 复现步骤

## 实验材料

这里提供实验归档和运行入口。补丁对应 `configs/versions.json` 中固定的上游提交，运行脚本使用环境变量指定源码、模型与数据路径。

权重和数据没有上传。训练完整过程约 38 小时，评测需要 MuJoCo 渲染环境。只想看结果时，直接阅读 `results` 与 `figures` 即可，不需要重新训练。

## 1. 准备源码

```bash
export VLA_WORKSPACE="$HOME/vla-work"
bash scripts/prepare_sources.sh
```

脚本克隆 OpenVLA、OFT 和 LIBERO 到独立目录，固定版本并应用补丁。发现已有目录时会停止，避免覆盖已有工作。下载失败后请检查目录与 Git 状态，不要直接覆盖。

`patches/oft-16gb.patch` 包含 8-bit 主干加载、k-bit 训练准备、非重入梯度检查点及 bitsandbytes 兼容处理。

服务器当前源码还有一行训练结束后加入的梯度裁剪。它没有参加已完成的训练，且只裁剪 VLA 参数，没有覆盖独立动作头。本发布补丁将其排除，避免让读者误以为 95.6% 是带裁剪训练的结果。

原版 OpenVLA 的评测补丁将注意力改为 SDPA，并允许在未启用 W&B 时绕过其导入失败。发布补丁对应归档时的源码状态，各次运行记录单独保留。

## 2. 配置环境

已运行的环境是 Linux、Python 3.10、RTX 5070 Ti 16GB、PyTorch 2.8.0+cu128。完整的关键版本见 `configs/versions.json`。

OFT 必须安装固定的 Transformers 分支。它的版本号也叫 `4.40.1`，但不等于 PyPI 同版本包。安装该分支时使用：

```bash
python -m pip install \
  "git+https://github.com/moojink/transformers-openvla-oft.git@bc339d9ad707454c0c115970db43c260067c61ab"
```

依赖安装以固定版本的上游 `SETUP.md` / `LIBERO.md` 为基础，再根据实际 GPU 选择 PyTorch。服务器用新 PyTorch 适配 Blackwell；安装时保留对应 CUDA 12.8 的版本，避免 `pip install -e .` 将 PyTorch 降回旧版。

服务器环境与上游依赖声明的差异：

- 上游声明 torch 2.2.0 / torchvision 0.17.0，实装为 2.8.0 / 0.23.0。
- TensorFlow 与 tensorflow-cpu 同时存在，且 2.15.0.post1 与声明的 2.15.0 不严格相等。
- opentelemetry-proto 要求的 protobuf 版本与当前环境不兼容。
- FastAPI / Uvicorn 属于可选的服务端推理依赖，当前使用本地评测入口。

版本表记录本次实验实际使用的环境。新环境应选择单一 TensorFlow 安装来源，并按使用路径处理 protobuf 依赖。原版 OpenVLA 与 OFT 使用独立环境，避免 Transformers 分支互相覆盖。

整理后的脚本默认使用各自源码目录的 `.venv/bin/python` 或 `.venv/bin/torchrun`。也可以用 `VLA_PYTHON` 和 `VLA_TORCHRUN` 指定已有解释器。

## 3. 准备模型与数据

- OFT 起点：Hugging Face `openvla/openvla-7b` 的完整基础权重目录。
- 数据：上游 OpenVLA / OFT 文档使用的 modified LIBERO RLDS 数据，目录内需有 `libero_spatial_no_noops`。
- 原版基线：分别使用 `openvla/openvla-7b-finetuned-libero-spatial`、`openvla/openvla-7b-finetuned-libero-object`、`openvla/openvla-7b-finetuned-libero-goal`。下载时以上游实际模型标识为准，本地目录名可以不同。

OFT 训练会通过 `update_auto_map` 及源码同步更新模型目录中的配置和 Python 文件。给 OFT 准备独立的基础权重副本，与原版 OpenVLA 分开管理。

动作数据为归一化后的 7 维控制指令；OFT 从 RLDS 轨迹构建 8 步动作块。训练配方见 `configs/oft_spatial.json`，数据获取与使用条款以原项目为准。

## 4. 训练

```bash
export VLA_WORKSPACE="$HOME/vla-work"
export MODEL_PATH="$HOME/vla-models/openvla-7b-oft"
export DATA_ROOT="$HOME/vla-data"
export RUN_ROOT="$HOME/vla-runs"
export GPU=0
bash scripts/train_oft.sh
```

训练入口为 OFT 的 `vla-scripts/finetune.py`。主干采用 8-bit 加载并添加 LoRA，独立 L1 动作头也参与优化。保存目录包含模型、处理器、归一化统计、LoRA adapter 和独立动作头。

仓库配置记录关键参数，执行命令见脚本，训练循环沿用固定版本的上游实现。

## 5. 评测

```bash
export CHECKPOINT="$HOME/vla-runs/your-10000-checkpoint"
export GPU=0
bash scripts/eval_oft.sh
```

默认 Spatial，每任务 50 次、seed 7、使用 LIBERO 默认初始状态。必须使用完整 checkpoint，不能只给 adapter。采用 8-bit 推理，防止模型和渲染器共同占用显存时溢出。

原版基线使用独立环境和官方对应套件权重：

```bash
VLA_WORKSPACE="$HOME/vla-work" \
VLA_PYTHON="$HOME/openvla-env/bin/python" \
CHECKPOINT="$HOME/vla-models/openvla-spatial" \
SUITE=spatial bash scripts/eval_openvla.sh
```

`MUJOCO_GL=egl` 和 `PYOPENGL_PLATFORM=egl` 让服务器通过 GPU 在内存中渲染图像，不需要连接显示器。评测仍然包含真实物理引擎步进与图像生成。

## 6. 复核记录

```bash
python3 scripts/verify_results.py
python3 scripts/summarize_eval.py path/to/EVAL-log.txt

# 仅重画图表，需要 matplotlib
python3 scripts/plot_results.py
```

公开评测日志保留任务、试验号、成功状态和汇总。`source_manifest.json` 记录原文件和发布文件哈希，用于交叉检查文件一致性。

运行入口通过 Shell 语法检查，补丁通过指定上游版本的应用检查，归档指标通过逐次日志交叉核对。
